## Persistent bounded trial and video recovery

Operator-installed project metadata assigns this project to the funded account
with ten image slots and three paid video slots, shared across providers.
Admission locks and refreshes the project row, reserves a slot in the same
transaction as the attempt, and preserves it across restarts. Preflight is free;
all admitted failures conservatively consume a slot, even before dispatch.
Students cannot create/reset the allowance. Reusing a request ID is idempotent;
changing its payload or requesting account is refused. Gallery/project updates
also refresh under lock to avoid overwriting concurrent counters.

Video submission atomically debits tokens and records dispatch. Paid bytes are
saved before optional fidelity scoring. Interrupted completion with saved bytes
remains retrievable with unavailable fidelity; an old unfinished attempt shows
interrupted and never automatically resubmits. Unreturned provider output still
requires operator reconciliation. This local synchronous trial is not a claim
that video has the durable image worker's capabilities. Classroom video stays off.
Shared saved-video access is distinct from requester-only interrupted-attempt
recovery and private submission metadata.

Focused real disposable PostgreSQL tests with mocked providers cover concurrent
duplicates (one paid call/charge), ten/three ceilings, cross-provider failure
accounting, fresh-session recovery, interrupted status and sharing isolation.
No production schema or persistence format migration was required.
