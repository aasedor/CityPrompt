# Tower storey options implementation plan

> **For agentic workers:** Use superpowers:executing-plans for integration, with independent bounded asset builders and review required by the RLASM workflow.

**Goal:** Add architectural height choices to the remaining local towers and verify ordinary browser editing.

**Architecture:** Exact native models remain unchanged. Regular towers use fixed lower/roof modules and complete repeated floors; complex towers select complete authored assemblies. Client/server share finite identity and native-target contracts.

**Tech Stack:** Python, Blender, FastAPI/PostGIS/MinIO, React/TypeScript/Vitest, native browser controls.

**Spec:** `docs/superpowers/specs/2026-10-27-tower-storey-options-design.md`.

## Global constraints

- Local-only, private additive installation; preserve source hashes and saved identities.
- No Z stretching, generic substitutions, paid generations, publication, push or deployment.
- Native counts retain exact original model bytes; unknown counts/revisions reject.
- One representative pilot receives independent pixel review before each finite scale-up.
- Exact target certification must pass final saved-zone placement, not merely planning.

## Review focus

- Reserved plots exceed model footprints: certify trusted dimensions independently of plot measurements.
- Discrete options have gaps: reject unbuilt counts in controls and final server validation.
- Stale or failed model checks: preserve saved geometry and permit retry/cancel.
- Fixed architectural datums: do not repeat entrances, bridge decks, trees or sky gardens as ordinary floors.
- Reload/native return: retain exact variant/source and never replace valid detail with massing.

## Tasks

1. **Finite source programmes** — `scripts/regular_tower_storeys.py`,
   `scripts/landmark_tower_storeys.py` and their narrow tests. Source-lock,
   measure, derive one representative per strategy, render exact GLBs and obtain
   independent review; then build the bounded remaining families. Output
   programme JSON and immutable GLBs outside Git. Test changed source/module
   bytes, datums, native preservation, finite counts, contacts and unit scale.
2. **Shared local runtime declarations** — new
   `frontend/src/data/localTowerStoreyPrograms.json`, helper and tests;
   extend `assetRegistry.ts`, `buildingStoreyProgram.ts` and
   `BuildingDesignControls.tsx`. RED tests assert Blue 15/25/40 heights, explicit
   landmark membership, native resolution, production gating and read-only
   derived height. Add a select for discrete choices; preserve current house
   controls and Brick/Vancouver contracts.
3. **Trusted target and recipe validation** — `building_flex_contract.py` and
   narrow backend tests. Read exact identity/dimension declarations from the
   shared contract; reject wrong asset, variant, source revision, scale, count
   and height. Exercise `_assert_ai_lego_recipes_are_current` using actual
   installed programme rows for all boundary/discrete cases. Preserve strict
   revision locks and private owner access.
4. **Private installation and local browser acceptance** — hydrate only exact
   needed local source/module bytes; verify hashes, conflict preservation and
   readback. Use one disposable tower project, test visible storey controls,
   detailed min/mid/max geometry, native return, save/reload and Undo/Redo.
   Compare low/aerial exact captures and inspect console errors. Complete one
   runtime review record per exact variant, with unrun gates left open.
5. **Final regression and delivery** — narrow Vitest/pytest, TypeScript, then
   full frontend run with bounded workers. Independently review integration.
   Inspect diff/check/status before coherent local commits. Upload completed
   source comparisons/screenshots to dated private Drive subfolder, verify
   metadata/readback, record IDs and missing outputs in a local manifest.
