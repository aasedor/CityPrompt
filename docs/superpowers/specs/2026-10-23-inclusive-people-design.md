# Inclusive architectural people — local eight-model pilot

User approved actual 3D models AND matching realistic picker images for the proposed first eight roles. Local only. Existing 23 people, previews, walking and saved scenes stay intact.

Models: white-cane user; guide-dog handler; manual wheelchair user; powered wheelchair user; older woman; older man with rollator; parent and child; parent with stroller. Natural friendly expressions in imagined photoreal picker previews; avoid pity/medical stereotypes. Aid geometry is physically present in the GLB. Use the established stylized human base for coherence, verified CC0 mobility-aid sources and separately documented authored derivatives. Family child anatomy must have child proportions rather than a uniformly scaled adult.

Selected approach: carefully fitted fixed natural poses for the eight local entries, using existing static detail loader/cache/placement/selection/undo/save/capture. Wheelchair users are seated; others standing. Animation-capable existing people retain all existing actions. Fixed-pose representations advertise only their verified action, including server-side validation. UI limitation: "Fixed pose. Move, rotate, duplicate or delete; motion is not animated in the 3D preview." AI rendering preserves the mobility aid/group arrangement and may depict the assigned action, but is not tested with new paid calls here. No invented walking/running/wheeling clips, collision/pathfinding, device specifications or accessibility compliance claims.

Alternatives considered: image-only would omit aids in actual scenes; forcing every new group into the old single-rig animation path would be unsafe. Fixed-pose static assets fit the user’s architectural-model request and existing loader, with explicit limits.

Contract: DetailAsset.peopleRepresentation?: {defaultAction:'standing'|'sitting'; supportedActions: readonly PeopleActionId[]; personCount:number; description:string; fixedPose:true}. New static entries use category People, kind object, metres/+Y up/+Z forward, ground datum0 and stable IDs people-inclusive-{white-cane,guide-dog,manual-wheelchair,power-wheelchair,older-woman,older-man-rollator,family-parent-child,family-stroller}. Existing DetailAsset.people remains reserved for animated rigs. New catalogue frontend/src/features/people/inclusivePeopleCatalogue.json; matching server metadata backend/app/data/inclusive_people.json. Both carry same representation contract. Source bytes and provenance are immutable/versioned outside source tree. Register in project_detail_models only after measured local assets exist.

Acceptance: all eight valid self-contained GLBs, provenance/hashes, evaluated metric bounds, foot/wheel/cane contact, hands/support contact, no accidental floors/backdrops; matching picker images with aids and correct person counts; 31 stable unique People entries; only supported actions accepted on client and server; actual browser load/selection/move/yaw/duplicate/delete/undo/save/reload/mixed capture; measured cost at stated counts. Test type-check and narrow frontend/backend regressions, final independent reviews. No push, live publication, source-policy changes, provider purchases or paid renders.
